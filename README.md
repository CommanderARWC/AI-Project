# Automatic Modulation Classification (AMC) under Simulated Channel Impairments

## 1. Project overview

**Automatic Modulation Classification (AMC)** identifies how a received radio signal was modulated, without prior knowledge of the transmitter. It is used in spectrum sensing, cognitive radio, software-defined radio and non-cooperative communications.

This project:

- generates a synthetic dataset of 8 modulations with RRC pulse shaping, multipath fading, Doppler spread, carrier frequency offset (CFO) and AWGN;
- trains a baseline 1D CNN and a hybrid CNN + BiLSTM + Transformer on identical data;
- evaluates overall accuracy, per-class behaviour (confusion matrix) and accuracy vs SNR.

The approach follows the idea of O'Shea et al., *Convolutional Radio Modulation Recognition Networks* (arXiv:1602.04105), which feeds raw I/Q into a CNN. **This project is not a reproduction of that paper and its numbers are not directly comparable** (different dataset, window length, classes and channel model; see [Limitations](#7-limitations-and-honest-caveats)).

## 2. Dataset

Generated by `Dataset.py`, saved as `modulation_dataset2.h5`.

### 2.1 Classes

| Label | Modulation | Family |
|---:|---|---|
| 0 | OOK | Amplitude |
| 1 | ASK | Amplitude |
| 2 | BPSK | Phase |
| 3 | QPSK | Phase |
| 4 | 8PSK | Phase |
| 5 | BFSK | Frequency |
| 6 | 4FSK | Frequency |
| 7 | 8FSK | Frequency |

### 2.2 Size and format

| Item | Value |
|---|---|
| Samples per example | 1024 complex samples |
| Samples per symbol | 8 (128 symbols per example) |
| SNR values | -1 to 19 dB in steps of 2 dB (11 values) |
| Examples per class per SNR | 500 |
| Total examples | 8 x 11 x 500 = **44,000** |
| Model input shape | `(2, 1024)`: channel 0 = I, channel 1 = Q |

HDF5 keys:

| Key | Shape | Meaning |
|---|---|---|
| `X` | `(44000, 2, 1024)` | I/Q samples, float32 |
| `Y` | `(44000,)` | class label 0-7, int64 |
| `SNR` | `(44000,)` | SNR in dB, int32 |

### 2.3 Signal generation

- **Linear modulations (OOK, ASK, BPSK, QPSK, 8PSK):** random symbols, upsampled by 8 and shaped with a **root-raised-cosine** filter (roll-off 0.35, span 6 symbols, 49 taps, unit energy). Symbol alphabets:
  - OOK: {0, 1}
  - ASK: {1, 3}
  - BPSK: {-1, +1}
  - QPSK: phases pi/4 + m*pi/2, m = 0..3
  - 8PSK: phases m*pi/4, m = 0..7
- **FSK modulations (BFSK, 4FSK, 8FSK):** continuous-phase FSK, with no RRC filter. Normalized tone frequencies are `[1, 3] / 8` (BFSK), `[1 ... 4] / 8` (4FSK) and `[1 ... 8] / 8` (8FSK) cycles/sample.

### 2.4 Channel impairments (applied in this order)

Each frame passes through a randomly drawn channel and then noise:

```text
r[n] = exp(j(2*pi*eps*n + phi)) * sum_{l=0}^{P-1} h_l[n] * s[n - l] + w[n]
```

| Step | Model | Parameters |
|---|---|---|
| 1. Multipath fading | Time-varying Rayleigh, exponential power-delay profile (unit sum) | P = 2-4 taps, complex Gaussian tap gains |
| 2. Doppler spread | Independent Doppler shift per tap | max normalized Doppler drawn from 1e-5 to 1e-3; each tap uniform in +/- max |
| 3. Carrier frequency offset | Constant complex rotation per example | CFO uniform in +/-0.01 cycles/sample, random phase in [0, 2 pi) |
| 4. Noise | AWGN, power set from the faded signal and the target SNR | SNR -1 to 19 dB |

**Important property:** a CFO of up to 0.01 cycles/sample over 1024 samples is up to about **10 full carrier rotations per example**. Together with fading and noise, this smears the received phase and makes closely related phase constellations (QPSK vs 8PSK) hard to tell apart.

### 2.5 Preprocessing before the model

Each example is normalized to **unit average power** (`x / sqrt(mean(x^2))`), so the network cannot use amplitude as a proxy for SNR. Data is randomly shuffled and split **70 / 15 / 15** (30,800 train / 6,600 validation / 6,600 test). The split is random, not stratified. The SNR of every example is kept for accuracy-vs-SNR curves.

## 3. Models

Both models use I and Q as the two input channels of a `Conv1d`.

### 3.1 Given model: 1D CNN (`given.py`)

```text
Input (2, 1024)
 -> Conv1d(2 -> 128, k=8)  -> BatchNorm -> ReLU -> MaxPool(2)
 -> Conv1d(128 -> 64, k=16) -> BatchNorm -> ReLU -> MaxPool(2)
 -> Flatten                                                        # 64 x 246 = 15,744
 -> Linear(128) -> ReLU -> Dropout(0.3)
 -> Linear(64)  -> ReLU
 -> Linear(8)
```

The flatten + dense layer ties every weight to a fixed time position in the window, so the model has little ability to relate symbols that are far apart in the frame. About **2.16 M** trainable parameters, mostly in the first dense layer.

### 3.2 Proposed model: CNN + BiLSTM + Transformer (`hybrid.py`)

```text
Input (2, 1024)
 -> Conv1d(2 -> 128, k=8)  -> BatchNorm -> ReLU -> MaxPool(2)      # 128 x 508
 -> Conv1d(128 -> 64, k=16) -> BatchNorm -> ReLU -> MaxPool(2)     # 64 x 246
 -> BiLSTM(hidden=128, 1 layer)                                    # 246 x 256
 -> TransformerEncoder(d_model=256, heads=8, ff=512, dropout=0.3, 1 layer)   # 246 x 256, no positional encoding
 -> Adaptive average pooling over time                             # 256
 -> Linear(128) -> ReLU -> Dropout(0.4)
 -> Linear(8)
```

Sequence length through the CNN: 1024 -> 1017 -> 508 -> 493 -> 246. No positional encoding is added to the Transformer because the BiLSTM already encodes order.

What each stage is for:

| Stage | Role |
|---|---|
| CNN | Local feature extraction (matched-filter-like patterns) |
| BiLSTM | Tracks how features evolve over time, in both directions |
| Transformer | Global self-attention across the whole window |
| Average pooling | Summarizes the sequence without tying features to a fixed position |

About **0.89 M** trainable parameters, so the gain is not due to a larger network.

### 3.3 Shared training setup

| Setting | Value |
|---|---|
| Loss | Cross-entropy |
| Optimizer | Adam, lr = 1e-3, no scheduler |
| Batch size | 256 |
| Epochs | 15 |
| Model selection | Weights from the epoch with best **validation accuracy** are restored before testing |

### 3.4 Differences between the two scripts

| | Given (`given.py`) | Proposed (`hybrid.py`) |
|---|---|---|
| Architecture | CNN | CNN + BiLSTM + Transformer |
| Data loading | Whole dataset in RAM | Streams each example from HDF5 (lower RAM, slower) |
| Split seed | Not fixed (unseeded permutation) | `np.random.seed(42)` |
| Outputs | Plots loss, confusion matrices and accuracy vs SNR; saves `model_weights.pt` | Saves `loss_vs_epoch.png`, `confusion_matrix.png`, `accuracy_vs_snr.png` and `model_weights2.pt` |

Because the split seeds differ, the two models were not tested on exactly the same 6,600 examples. Fixing one shared seed is recommended for a strictly fair comparison.

## 4. Results

All numbers are from **one training run** on a 6,600-example test set. The standard error on overall accuracy is roughly 0.2-0.4 percentage points (about 0.4 for the CNN, about 0.2 for the hybrid).

### 4.1 Overall accuracy

| Model | Test accuracy |
|---|---:|
| Given CNN | 87.42% |
| Proposed hybrid | **96.30%** |

Improvement on the same dataset: **+8.88 percentage points**.

### 4.2 Per-class accuracy

| Class | Test frames | Given CNN | Proposed | Change |
|---|---:|---:|---:|---:|
| OOK | 830 | 99.76% | 100.00% | +0.24 |
| ASK | 839 | 99.27% | 99.64% | +0.37 |
| BPSK | 798 | 99.26% | 99.62% | +0.36 |
| **QPSK** | 856 | **39.93%** | **85.51%** | **+45.58** |
| **8PSK** | 853 | **62.44%** | **88.16%** | **+25.72** |
| BFSK | 819 | 100.00% | 100.00% | 0.00 |
| 4FSK | 809 | 100.00% | 98.39% | -1.61 |
| 8FSK | 796 | 99.51% | 100.00% | +0.49 |
| **Overall** | 6600 | **87.42%** | **96.30%** | **+8.88** |

**Almost the whole improvement is in QPSK and 8PSK.** Both models classify the amplitude and frequency modulations almost perfectly. The only class that got worse is 4FSK, by 1.61 points.

### 4.3 Confusion matrix (proposed model)

Nearly all errors are between QPSK and 8PSK:

- 123 QPSK frames (14.4%) are classified as 8PSK;
- 101 8PSK frames (11.8%) are classified as QPSK;
- 13 frames of 4FSK are classified as 8FSK;
- no other off-diagonal cell exceeds 3 frames.

## 5. Discussion: why QPSK vs 8PSK?

QPSK and 8PSK differ only in the number of phase states. In this dataset the four QPSK phases (pi/4 + m*pi/2) are a subset of the eight 8PSK phases (m*pi/4), so a QPSK frame looks like an 8PSK frame that uses half of its points. Phase and frequency offset, fading and noise blur this difference, and deciding that only four states are used needs evidence from the whole frame.

The baseline's flattened dense classifier sees only a local-feature map and cannot easily relate symbols far apart in the frame. The BiLSTM and self-attention layer can collect evidence over all positions, which is a plausible reason for the large gains. **No ablation was run**, so the separate contribution of the BiLSTM and the Transformer is not measured, and QPSK/8PSK remains the hardest pair.

## 7. Limitations and honest caveats

- **Single run, no confidence intervals.** Differences of a fraction of a point are within noise.
- **Different test splits.** The baseline and proposed scripts use different shuffles, so they were not tested on an identical set of examples.
- **No ablation.** The separate contribution of the BiLSTM and the Transformer is not measured.
- **Synthetic data only.** Eight classes, a fixed symbol rate, pulse shape and frame length; real over-the-air captures may behave differently.
- **Not comparable to published numbers.** Different dataset, window length, classes and channel model from the RadioML / O'Shea et al. setting.
- **Inference time was not measured.**
- **Reproducibility gaps.** No seeds in `Dataset.py`, PyTorch not seeded, library versions not recorded.
- **QPSK/8PSK remains the main error source** (about 12-14% of frames in each direction).
